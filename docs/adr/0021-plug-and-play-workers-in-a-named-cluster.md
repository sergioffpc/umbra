# Plug-and-play Workers in a named Cluster

> **Amended by [ADR 0023](0023-x86-64-only.md).** `umbra render` runs on a target machine: the P620, the operator's workstation, or the R630.
>
> **Amended by [ADR 0025](0025-one-x86-64-v3-release-image.md).** A release Worker pulls the one `X.Y.Z` image; there is no image variant per CPU to choose.

Workers run permanently and find Coordinators on their own. A Coordinator that has a Render Job announces it on the LAN with DNS-SD, and every idle Worker of its Cluster joins. There is no launch script. Decided with the owner on 2026-11-07. This supersedes [ADR 0018](0018-sessions-launched-from-the-operators-machine.md), whose `scripts/workers up` built, started and restarted the Workers of each Session. It also amends [ADR 0003](0003-pbrt-v4-scene-files-parsed-on-the-coordinator.md), [ADR 0012](0012-per-cpu-binaries-locked-to-one-commit.md), [ADR 0016](0016-one-render-job-per-quic-connection.md) and [ADR 0017](0017-one-worker-per-numa-node.md), which relied on that script.

With the script, every Render Job paid for SSH, a build or pull on every host, and a host list the operator had to maintain. Plug and play turns this around. The operator starts one Worker per NUMA node on each host and leaves it running, and `umbra render` on any machine uses whichever Workers of its Cluster are up.

- **Cluster.** Every Coordinator and Worker belongs to one Cluster. Its name comes from `--cluster <name>` or `UMBRA_CLUSTER`, and is `default` when neither is set. A Cluster Name is a DNS label: lowercase letters, digits and `-`, at most 63 characters. A Coordinator works only with Workers of its own Cluster, so two Clusters can share a LAN without seeing each other, for example to benchmark the R630 alone. The name is a label, not a secret. Like the Session identifier it replaces, it prevents mistakes of operation, and hostile nodes stay out of scope ([ADR 0016](0016-one-render-job-per-quic-connection.md)).
- **Discovery by DNS-SD.** A Coordinator announces each Render Job over multicast DNS ([RFC 6762](https://www.rfc-editor.org/rfc/rfc6762), [RFC 6763](https://www.rfc-editor.org/rfc/rfc6763)) as an instance of the service `_umbra._udp`. The instance is named by a random Render Job identifier, its SRV record carries the QUIC port, and its TXT record carries `cluster=<name>`. Discovery uses the `mdns-sd` crate, which is pure Rust and needs no Avahi or Bonjour daemon. Workers browse for the service and ignore other Clusters. No address is configured anywhere.
- **Start-up order, kept from ADR 0018.** The Coordinator parses the Scene File and builds the Scene and the Reproduction Record. Only then does it open its UDP port and announce the Render Job. On an Invalid Scene File it exits before announcing anything, so no Worker ever joins a Scene that cannot be rendered. It does not wait for Workers: the Render Job starts with the first `RequestWork`, local or remote. A Worker that starts later joins the Render Job already in progress.
- **Long-running Workers.** `umbra worker` runs until it is stopped. While idle, it browses for Render Jobs. When one of its Cluster is announced, the Worker connects, sends `Hello`, receives the whole Scene and asks for work, as before. When the connection closes, it drops the Scene and is idle again. A Worker serves one Render Job at a time. If several are announced, it joins the one it discovered first, so concurrent Coordinators share the Cluster without a queue.
- **Rejoining after a failure.** The connection can end with `Fatal`, `WORKER_TIMED_OUT`, a lost Coordinator or a failed connection. In those cases the Worker rejoins the same Render Job for as long as it is announced: after 2 s, then 10 s, then every 30 s. The count resets once the Worker delivers a Work Result. A retry cannot cure `REJECTED` or `PROTOCOL_ERROR`, so after either the Worker never rejoins that Render Job. After `FINISHED` or `JOB_CANCELLED` it simply returns to idle.
- **Bounded by the Coordinator.** The Coordinator counts failures per Worker Slot, meaning the host and NUMA node a Worker reports in `Hello`. If a slot's Workers fail three times in a row without delivering a Work Result in between, the Coordinator refuses that slot for the rest of the Render Job with `Reject { TooManyFailures }`. The count lives in the Coordinator because a Worker that the kernel kills for running out of memory, and that its supervisor then restarts, remembers nothing.
- **Supervision is the host's job.** A Worker process that dies, from an uncaught panic or an out-of-memory kill, is restarted by whatever started it. For releases that is `docker run --restart unless-stopped`; for development it is the operator's terminal. The README documents both.
- **End of a Render Job.** The Coordinator withdraws its announcement before it sends `JobFinished` or closes connections with `JOB_CANCELLED`, so no Worker joins a Render Job that is ending.
- **Heartbeat from `Welcome`, kept from ADR 0018.** A Worker opens its heartbeat stream right after `Welcome`, and while it loads, the heartbeat carries loading progress. The 5 s death rule therefore covers a loading Worker. A Worker whose loading stops progressing is shown as `stalled`, never declared dead.
- **Coordinator on the operator's machine, kept from ADR 0018.** `umbra render` runs wherever the operator runs it, reads the Scene File there, and writes the image and the Render Job Report there. For large Scenes the operator runs it on the wired P620. With no Worker alive and no local Worker, the status line shows `waiting: no Workers` until a Worker joins or the operator presses Ctrl-C.

## Considered options

- **The launch script of ADR 0018**: superseded. It rebuilt or pulled on every host and restarted Workers by exit code. But every Render Job paid that cost, and a Worker could not join a Session it had not been started with.
- **Workers announce themselves and the Coordinator connects to them**: rejected. Each Worker would become a QUIC server, so every Worker host would have to open UDP ports in its firewall, two on the R630. The stream ownership of [arc42 §8.13](../architecture/08-crosscutting-concepts.md#813-wire-protocol) would also invert. When the Coordinator announces, only the machines that run Coordinators open a port, as before.
- **A fixed Coordinator address given to each Worker, with retries**: rejected. The Coordinator runs on whichever machine the operator is using, so every Worker would need every possible address.
- **A secret cookie checked by a challenge in the handshake, as in Erlang**: rejected. It would authenticate nodes, but hostile nodes are out of scope and the TLS certificate is not verified either ([ADR 0016](0016-one-render-job-per-quic-connection.md)). A name is enough to keep honest Clusters apart.
- **A custom UDP broadcast beacon**: rejected. DNS-SD does the same job, and standard tools show what is announced, such as `avahi-browse -r _umbra._udp`.
- **Filtering Workers by commit at discovery**: rejected. Under this rule, a Worker on another commit stays away silently. Instead it joins and the handshake refuses it, so the operator sees the refusal on the Coordinator's terminal, with the Worker's host and commit.

## Consequences

- Building is no longer automated. After changing commit, the operator rebuilds and restarts the Worker on every host, or pulls and restarts the release image. Until then the Coordinator refuses those Workers with `CommitMismatch` and logs which hosts are behind.
- Every machine must let mDNS through: UDP 5353 from the LAN, multicast group 224.0.0.251. The R630's nftables, which admits only SSH, gains that rule. Machines that run Coordinators still open UDP 7470. Containers run with `--network host`.
- Discovery depends on multicast reaching every host. If a network ever filters it, the fallback is a fixed `--coordinator` address on the Worker, to be decided then.
- A Worker holds no Scene between Render Jobs, so an idle Worker uses almost no memory. Every Render Job still sends the whole Scene to every Worker ([ADR 0016](0016-one-render-job-per-quic-connection.md)).
- `umbra worker` no longer exits at the end of a Render Job. It exits 0 when stopped with Ctrl-C or `SIGTERM`. Exit codes are no longer a contract with a script.
- The Session identifier, the readiness line on stderr and the host list are gone. `Hello` carries the Cluster Name and the Worker's NUMA node. The Render Job Report counts the Workers and the refusals of each Worker Slot.
